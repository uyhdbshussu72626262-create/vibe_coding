# Daynora 已知问题清单

记录时间：2026-10-01　版本：0.1.0

---

## 一、AI 联网检索

### 1.1 检索结果与提问相关性不稳定（严重度：高）

- **现象**：同一句提问，有时能拿到相关结果，有时回答与问题几乎无关。
- **原因**：
  - 检索由应用完成（搜索 → 取摘要/正文 → 注入提示词），检索质量直接决定回答质量；
  - 搜索源依赖 Bing 网页结果、Google News RSS、维基百科检索 API，均可能返回营销页、聚合页或过时页面；
  - 中文长尾问题（口语化、含专有名词）在通用搜索引擎上命中率偏低。
- **影响**：用户对"AI 能不能上网"产生怀疑，需要人工判断答案可信度。
- **可能方向**（本轮不实施）：接入更专一的检索服务（SearXNG 自建实例、Tavily、Brave Search、Serper 等）；对结果做相关性二次排序；对中文查询做关键词改写后再检索。

### 1.2 只抓取前两条页面正文（严重度：中）

- **现象**：资料面窄，容易只看到一两个站点观点。
- **原因**：抓取正文有时间成本（每条最多 5 秒），当前限制为前 2 条、每页最多约 2200 字。
- **影响**：涉及对比、时间线类问题时信息不完整。

### 1.3 现代网页抓取失败（严重度：中）

- **现象**：部分链接点开能看到内容，但 AI 说"资料不足"。
- **原因**：正文依赖 JavaScript 渲染（SPA）、需要登录、受付费墙或反爬限制的站点，抓取到的 HTML 里没有正文。
- **影响**：对知乎、微信公众号、部分技术博客等内容源效果差。
- **备注**：需要登录的站点属于已知限制，不计划绕过。

### 1.4 检索过程没有进度反馈（严重度：中）

- **现象**：点击发送后有几秒"没有反应"，然后才开始输出。
- **原因**：检索在模型请求之前同步执行，界面只显示"生成中"。
- **影响**：用户会以为软件卡住，体验上像"卡顿"。
- **可能方向**：把检索阶段单独展示（例如"正在检索资料…"+"已找到 N 条来源"）。

### 1.5 检索是单轮的（严重度：高）

- **现象**：模型无法"再查一次"，只能基于一次性注入的资料作答。
- **原因**：当前实现是"应用代检索（RAG）"，而不是把 `web_search` 作为工具交给模型做多轮 agent 调用。
- **影响**：复杂问题（需要先查 A、再根据 A 查 B）无法完成。
- **可能方向**：改用 Function Calling 让模型自主决定是否检索、检索什么、是否二次检索。

### 1.6 链接有效性未校验（严重度：中）

- **现象**：回答里可能出现打不开或与内容不符的链接。
- **原因**：模型可能自行"拼"链接，应用只提供参考来源，不校验模型引用的 URL。
- **影响**：用户点开发现 404 或无关页面。

## 二、模型与提供商支持

### 2.1 内置提供商偏少（严重度：高）

- **现象**：只有 DeepSeek、OpenAI、Moonshot、SiliconFlow、OpenRouter、自定义 六种预设。
- **影响**：想用其他服务（如智谱、通义、Groq、Together、本地 Ollama/vLLM）必须手填 Base URL 与模型名。
- **可能方向**：扩充预设；支持从 `GET /v1/models` 拉取模型列表供选择。

### 2.2 无模型能力标注（严重度：高）

- **现象**：界面上只是一个可编辑的模型名输入框，看不出该模型是否支持图片输入、工具调用、长上下文。
- **影响**：用户选了不支持视觉的模型上传图片，只能得到"我看不到图片"的回复；选了不支持工具调用的模型，"建议修改"功能无效。
- **可能方向**：为每个预设维护能力标记，并在界面上提示。

### 2.3 只支持 Chat Completions 接口形态（严重度：中）

- **现象**：只调用 `POST {base_url}/chat/completions`。
- **影响**：不支持 OpenAI Responses API 以及只暴露新接口的服务；部分厂商的差异字段被忽略。

### 2.4 缺少服务商要求的可选请求头（严重度：低）

- **现象**：未发送 OpenRouter 推荐的 `HTTP-Referer` / `X-Title` 等标识头。
- **影响**：在 OpenRouter 的排行榜统计与部分风控策略下可能受影响。

### 2.5 SSE 解析假设 OpenAI 兼容格式（严重度：低）

- **现象**：按 `choices[0].delta` 解析流式内容。
- **影响**：个别厂商返回变体结构时，可能出现"没有输出"或解析中断。

## 三、AI 对话体验

### 3.1 没有跨会话记忆（严重度：中）

- 每个会话独立，新开对话不会记得之前对话的内容；也没有"长期记忆"。

### 3.2 不能重新生成 / 编辑消息（严重度：中）

- 只能重试上一条提问或新开一轮；不能编辑历史提问、不能对单条回答重新生成。

### 3.3 新会话自动起标题会多消耗一次请求（严重度：低）

- 首轮问答结束后会额外调用一次模型生成短标题；成本敏感用户可感知。

### 3.4 Token 统计较粗（严重度：低）

- 仅显示一次请求的 prompt / completion / total，没有会话累计与成本估算。

### 3.5 图片附件占用数据库空间（严重度：中）

- 图片以 base64 编码（加密后）存入 SQLite，单张上限 8MB，长期使用数据库会明显变大。
- 没有图片压缩、去重或清理入口（仅能删除整条会话）。

### 3.6 系统提示词是全局的（严重度：低）

- 无法为单个会话或单次提问设置不同的系统提示词。

## 四、任务与专注计时

### 4.1 计时只有倒计时（严重度：中）

- 没有正计时模式；没有专注历史、每日/每周专注时长统计。

### 4.2 重复规则有限（严重度：中）

- 仅支持不重复 / 每天 / 每周 / 工作日，不支持"每 N 天""每月某日""自定义 RRULE"。

### 4.3 撤销与快照有上限（严重度：低）

- 任务撤销栈保留 15 步；AI 计划修改快照保留 20 份，超出后最早记录被丢弃。

### 4.4 提醒依赖应用运行（严重度：中）

- 提醒由前端每 30 秒轮询触发，关闭软件后不会提醒；没有系统级计划任务。

### 4.5 子任务模块已移除（严重度：低）

- 按需求在编辑器中删除了子任务功能，历史数据字段仍保留但不再展示。

## 五、平台与数据

### 5.1 仅 Windows（严重度：中）

- 打包目标为 Windows（NSIS 安装包 + 便携版）；托盘、开机自启、密钥加密使用 Windows 专有实现，尚未适配 macOS/Linux。

### 5.2 无云同步、无多设备（严重度：中）

- 数据仅存本机 SQLite；换电脑需手动导出/导入。

### 5.3 API Key 绑定本机（严重度：低）

- 密钥用 Windows DPAPI 加密，换机器或重装系统后需要重新填写。

### 5.4 数据库迁移在启动时执行（严重度：低）

- 升级前会自动做一次文件级备份；但跨大版本升级仍建议先手动备份数据目录。

### 5.5 AI 会话内容加密（已缓解）

- `ai_messages.content`、会话标题、图片均使用 DPAPI 加密后落库；文件系统层面依然可以被同一 Windows 账户下的程序读取。

## 六、工程质量与发布

### 6.1 打包体积偏大（严重度：低）

- 前端单个 JS 产物约 646KB（含 KaTeX、highlight.js、marked、DOMPurify），未做代码分割。

### 6.2 测试覆盖有限（严重度：低）

- 后端 14 项（单元 + 集成）、前端 30 项逻辑单测；缺少端到端 UI 自动化测试。

### 6.3 无 CI / 无 lint（严重度：低）

- 没有 GitHub Actions 流水线，也没有 ESLint/Prettier 配置，风格靠人工约束。

### 6.4 无自动更新（严重度：低）

- 更新配置已预留但处于关闭状态，新版本需要用户手动下载替换。

### 6.5 无崩溃日志与遥测（严重度：低）

- 崩溃后没有本地日志留存与上报通道，问题复现依赖用户描述。

### 6.6 代码仍有拆分空间（严重度：低）

- `src/app.ts` 约 1800 行，承担状态、事件分发与部分视图渲染；任务视图（卡片/编辑器/看板）尚未独立成模块。

### 6.7 部分文案未走多语言（严重度：低）

- 个别提示语（如专注界面状态、部分按钮）为硬编码中文。

---

## 七、明确的"不做"项

- 不绕过需要登录、付费墙或验证码的站点。
- 不内置任何 API Key；AI 功能必须由使用者自行配置。
- 不采集用户数据、不上报使用行为。
